# ВУ·Пакет

Небольшой платный сервис: организация без кадровика вводит свои реквизиты и получает пакет документов по воинскому учёту в Word.

**Что в пакете:**
- приказ об организации воинского учёта;
- функциональные обязанности ответственного;
- план работы на год;
- журнал проверок;
- письмо в военкомат;
- памятка;
- файл напоминаний `.ics` для календаря.

**Как это работает:** анкета → предпросмотр → оплата ЮKassa (разовая) → скачивание ZIP.

Исследование рынка, экономика и план коммерческого теста: [docs/RESEARCH.md](docs/RESEARCH.md). Расчёт экономики: `python3 docs/economics.py`.

## Стек и принципы

- Python 3.11+, стандартная библиотека (`http.server`, `sqlite3`) и `python-docx`. ИИ не используется: тексты документов детерминированы и лежат в `vupaket/documents.py`.
- Секреты только в переменных окружения на сервере.
- Персональные данные работников не собираются. Анкета содержит ФИО руководителя и ответственного и e-mail для чека. Неоплаченные анкеты удаляются через `VU_ORDER_TTL_DAYS` дней.
- Аналитика (`events`) хранит только название события, хэш заказа и utm. Анкетные данные туда не попадают, это проверяется тестом. В Метрике Вебвизор выключен.
- Оплата: платёж ЮKassa с чеком (54-ФЗ). Уведомлению не доверяем: статус, сумма, валюта и заказ перепроверяются через API. Повторные уведомления безопасны. Если вебхук задержался, статус запрашивается при возврате покупателя.
- Ограничения частоты запросов на создание заказа, оплату, скачивание и вебхук. Размер тела запроса ограничен 20 КБ.
- Ссылка на заказ — секретный токен. Отдаётся с заголовком `Referrer-Policy: no-referrer`, в логах маскируется.

## Структура

```
vupaket/documents.py   тексты и структура 6 документов + .ics
vupaket/render.py      DOCX (python-docx), HTML-предпросмотр, ZIP
vupaket/validation.py  проверка анкеты, контрольная сумма ИНН
vupaket/server.py      маршруты, ограничение частоты, вебхук
vupaket/payments.py    ЮKassa
vupaket/db.py          SQLite: заказы, платежи, события
vupaket/pages.py       HTML/CSS страниц (мобильная вёрстка)
tests/test_app.py      22 теста: документы, анкета, демо- и платёжный сценарии, аналитика без ПДн
```

## Локальный запуск

```bash
cd vu-paket
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
VU_DEMO_PAYMENTS=1 VU_ADMIN_KEY=dev python3 run.py     # http://127.0.0.1:8080
python3 -m unittest discover -s tests
```

`VU_DEMO_PAYMENTS=1` включает **демо-оплату без денег**. На странице это явно подписано, в выручку в `/admin` такие заказы не попадают. В проде должно быть `0`.

## Маршруты

| Путь | Назначение |
|---|---|
| `/` | лендинг (utm сохраняются в cookie на 30 дней) |
| `/form` → `POST /order` | анкета |
| `/order/<token>` | предпросмотр, ожидание оплаты или страница «оплачено» |
| `/order/<token>/edit` | правка анкеты до оплаты |
| `POST /order/<token>/pay` | создание платежа ЮKassa |
| `/order/<token>/download` | ZIP, только после оплаты |
| `POST /yookassa/webhook` | уведомления ЮKassa |
| `/sample` | пример документов для вымышленной ООО |
| `/offer`, `/privacy` | черновики оферты и политики ПДн |
| `/admin?key=...` | воронка по utm, заказы, реальная выручка |
| `/healthz` | `payments=ready/demo/off`, `seller=ok/missing` |

## Развёртывание (Docker + Caddy)

1. Сервер: подойдёт существующий VPS с PR Monitor (`/opt/pr-monitor`, там уже работает Caddy в Docker). Создайте `vu-paket/.env` из `.env.example`.
2. Добавьте сервис в общий `docker-compose.yml` PR Monitor:
   ```yaml
   vu-paket:
     build: ./vu-paket
     restart: unless-stopped
     env_file: ./vu-paket/.env
     volumes:
       - ./vu-paket/data:/app/data
     expose:
       - "8080"
   ```
3. DNS: A-запись поддомена на IP сервера. В `deploy/Caddyfile` добавьте:
   ```
   vu-paket.example.ru {
       encode gzip
       reverse_proxy vu-paket:8080
   }
   ```
   В `.env` выставьте `VU_TRUST_PROXY=1` и `VU_PUBLIC_URL=https://vu-paket.example.ru`.
4. `docker compose up -d --build vu-paket caddy`. Отдельный сервер тоже подойдёт: `vu-paket/docker-compose.yml` слушает `127.0.0.1:8080`, перед ним нужен любой HTTPS-прокси.
5. ЮKassa: подключите магазин, «Чеки от ЮKassa», укажите HTTP-уведомления на `https://<домен>/yookassa/webhook` (события `payment.succeeded` и `payment.canceled`).
6. Проверка: `/healthz` = `ok payments=ready seller=ok`. Сделайте реальную покупку своей картой: чек, вебхук, скачивание, запись в `/admin`. Затем сделайте возврат в кабинете ЮKassa.
7. Резервная копия: `data/vu.db` (SQLite).

## Что нужно до приёма денег

- Реквизиты продавца `VU_SELLER_*`. Без них в подвале висит предупреждение.
- Договор с ЮKassa и выбор решения для чеков. Ставку НДС в чеке (`YOOKASSA_VAT_CODE`) согласуйте с бухгалтером.
- Уведомление в Роскомнадзор об обработке ПДн, если его ещё нет.
- Юридическая проверка оферты и политики: сейчас это черновики, помечены на страницах.
- Проверка текстов документов практикующим специалистом по воинскому учёту.
