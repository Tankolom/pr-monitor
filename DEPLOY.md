# Публичное развертывание PR Monitor

Цель пилотного запуска: дать коллегам ссылку, логин и пароль, чтобы они могли открыть продукт онлайн, создать/посмотреть проекты, запустить ручной сбор и скачать Excel.

## Что понадобится

1. VPS/cloud-сервер с Ubuntu.
2. Домен или поддомен, например `prmonitor.example.ru`.
3. Docker и Docker Compose на сервере.
4. Открытые порты `80` и `443`.

## Важный режим для тестов

По умолчанию запускаются только:

- `app` - веб-приложение;
- `caddy` - HTTPS-прокси.

Фоновый сбор `worker` вынесен в отдельный профиль. Это сделано специально, чтобы на тестах не тратить лимиты API каждые 30 минут.

## DNS

В панели домена создайте `A`-запись:

```text
prmonitor.example.ru -> IP_ВАШЕГО_СЕРВЕРА
```

Подождите, пока запись применится.

## Подготовка проекта на сервере

Скопируйте папку проекта на сервер, например:

```bash
/opt/pr-monitor
```

Внутри папки создайте `.env`:

```bash
cp .env.example .env
```

Откройте `.env` и замените:

```text
DOMAIN=prmonitor.example.ru
ACME_EMAIL=ваш-email@example.ru
MENTION_MONITOR_PASSWORD=любой-длинный-пароль
MENTION_MONITOR_ADMIN_PASSWORD=отдельный-сильный-пароль-админа
COLLECT_INTERVAL_MINUTES=30
```

`MENTION_MONITOR_PASSWORD` сейчас нужен только чтобы compose не запускался с пустым секретом. Вход пользователей уже управляется внутри приложения через логины и пароли.

## Запуск сайта

```bash
docker compose up -d --build
```

Откройте:

```text
https://prmonitor.example.ru
```

Первый вход:

```text
логин: admin
пароль: admin12345
```

После входа сразу зайдите в **Админ-панель** и создайте отдельные логины для коллег.

## Ручной сбор

Для тестового режима коллеги запускают сбор через кнопку в интерфейсе. Это безопаснее для лимитов API.

## Включить фоновый сбор позже

Когда будете готовы к регулярному мониторингу:

```bash
docker compose --profile worker up -d
```

Остановить фоновый сбор:

```bash
docker compose stop worker
```

## Обновление версии

После изменения файлов:

```bash
docker compose up -d --build
```

Если включен worker:

```bash
docker compose --profile worker up -d --build
```

## Резервные копии базы

Теперь в проекте есть встроенная команда резервного копирования SQLite с ротацией:

```bash
python run.py --config config.json backup --keep 14
```

Рекомендуемый вариант на сервере — запускать её раз в день и складывать копии в `data/backups`.

Пример ежедневного задания:

```bash
0 3 * * * cd /opt/pr-monitor && /usr/bin/python3 run.py --config config.json backup --keep 14
```

## Где данные

- `data/mentions.db` - база упоминаний и пользователи;
- `data/secrets.json` - API-ключи и токены;
- `data/raw` - сырые ответы источников;
- `outputs/reports` - Excel-отчеты;
- `config.json` - проекты, источники, настройки.

## Что проверить перед тем, как дать ссылку

1. Страница открывается по HTTPS.
2. Вход под админом работает, и пароль после первого входа уже заменён на свой.
3. В админ-панели созданы пользователи коллег.
4. В настройках подключены VK, Serper, Яндекс и другие нужные источники.
5. Кнопка **Запустить срез** работает.
6. Кнопка **Сформировать Excel** скачивает отчет.

## Важно для безопасности

- Не отдавайте коллегам общий `admin`, создайте отдельные аккаунты.
- После первого запуска обязательно смените пароль admin.
- Не публикуйте `data/secrets.json` в открытый репозиторий.
- Делайте резервную копию папки `data`.
